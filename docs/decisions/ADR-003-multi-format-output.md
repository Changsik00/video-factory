# ADR-003: 결과물은 하나의 대본에서 HTML·PDF·MP4 세 형식으로 낸다 (PPTX 제외)

## 📚 Context
ADR-001 은 첫 제품을 "무음 이펙트 쇼케이스 영상"으로 정했다. spec-01-01~03 은 HyperFrames 블록·자막 컴포넌트를 영상으로 렌더하는 것만 검증했다 (`docs/tool-findings.md`). 2026-10-30 사용자가 결과물 형식을 넓혔다.
- 정적 자료는 PDF, 프레젠테이션은 HTML(화살표로 진행), 자동 재생은 MP4.
- 하나의 스크립트(대본)에서 에이전트가 이미지·인터랙션을 만들고 진행한다.
- PPTX 는 하지 않는다.

확인한 사실 (HyperFrames CLI 0.8.206 도움말 직접 확인):
- `render --format` 은 mp4, webm, mov, gif, png-sequence, hls 이다. PDF·PPTX 출력은 없다.
- `snapshot` 은 지정 시각의 프레임을 PNG 로 저장한다.
- `present` 는 슬라이드 덱을 발표자 모드로 서빙한다. (spec-01-04 실측 후 갱신) `slideshow` 스킬을 설치해 3장 덱으로 시험했고, **ArrowRight/Space 다음, ArrowLeft 이전**이 헤드리스 Chrome 의 실제 키 입력으로 동작했다. fragment 단계도 진행했다. 전환 애니메이션 유무와 청중 화면 동기화는 확인하지 못했다.
- 컴포지션은 `1920x1080` 고정, `overflow: hidden`, GSAP 타임라인으로 움직이는 HTML 이다 (예: `caption-emoji-pop`). 그대로 인쇄하면 애니메이션 중간 상태가 찍히거나 잘린다.

## 🎯 Decision
1. 출력 형식은 세 가지다. 용도가 다르다.

| 형식 | 용도 | 만드는 방법 |
|---|---|---|
| HTML | 프레젠테이션 (화살표로 단계 진행) | 슬라이드 HTML 을 브라우저에서 연다 |
| PDF | 정적 자료 | 같은 **장면 파일**에서 인쇄용 페이지를 생성(모든 타임라인을 끝으로 보낸 최종 상태)해 헤드리스 Chrome 으로 PDF 출력. 영상용 HTML 을 그대로 인쇄하는 것은 아님 |
| MP4 | 자동 재생 | 같은 컴포지션(루트 + 장면 파일)을 `hyperframes render` |

2. 원본은 하나의 대본(콘텐츠 명세, Content Manifest)이다. 슬라이드는 "장면 파일 하나 + 순서 있는 단계(fragment 시각)"로 정의하고 장면마다 지속 시간을 둔다. **(2026-10-30 수정, spec-01-04 실측)** 컴포지션은 **루트(`main`) + 장면 파일 마운트(`data-composition-src`)** 구조여야 하며, 이 구조에서 같은 파일이 `present`(키 진행)와 `render`(MP4)에 모두 쓰였다. 최상위 장면을 한 파일에 직접 두고 루트가 없으면 `render` 가 첫 장면만 남긴다(4초). PDF 는 같은 장면 파일의 스타일·본문·스크립트를 재사용해 만든 인쇄용 페이지에서 최종 상태를 낸다.
3. PPTX 는 하지 않는다. 사용자가 제외했다.
4. 음성·음악·효과음은 ADR-001 을 유지한다. 사용자가 요청할 때만 추가한다.
5. ADR-001 은 "음성 없음, 자막만" 부분이 유효하다. "결과물은 영상" 가정은 이 ADR 로 대체한다.

## 📊 Consequences
- **긍정**: 한 번 정의한 슬라이드가 세 형식에 쓰인다. 문구 수정 시 세 형식을 다시 뽑을 수 있다. 프로젝트 원칙 2·3(명세 중심, 형식·컴포넌트·워크플로 분리)과 맞는다.
- **검증 상태 (spec-01-04, 글자·색만 있는 3장 덱 1개 기준)**: HTML 진행(키 입력), MP4(16초, 프레임 확인), 벡터 PDF(3쪽, 글자 231자 추출)가 모두 같은 장면 파일에서 나왔다. **아직 검증하지 못한 것**: 이미지·영상·WebGL 요소가 있는 장면의 PDF, 분기 슬라이드(`slideSequences`)와 소리가 있을 때의 렌더, 전환 애니메이션, 사용자가 직접 브라우저에서 눌러 본 체감. 장면 파일은 인쇄용 페이지에서도 실행되도록 작성해야 한다(전역 `const` 충돌 회피, 런타임 없이 `window.__timelines` 가정 금지). 슬라이드는 16:9 고정 페이지로 설계한다.
- **중립**: PDF 는 글자가 벡터로 남는 방식(HTML 인쇄)을 택한다. 편집 가능한 PPTX 는 범위 밖이다.

## 🔀 Alternatives
- **PNG 를 묶은 PDF**: 비채택 — 글자 선택·검색이 안 되고 화질이 해상도에 묶인다.
- **PPTX 포함**: 비채택(사용자 결정) — HyperFrames 방식(HTML·GSAP)의 이펙트를 옮길 수 없고 PowerPoint 고유 전환만 가능하며 별도 도구가 필요하다 (일반 지식, 미시험).
- **영상만**: ADR-001 원안 — 비채택 이유: 정적 자료와 발표 용도를 놓친다.

## 📌 Status
Accepted (2026-10-30, 사용자 결정). 같은 날 spec-01-04 실측 결과로 결정 2 와 PDF 방법을 수정했다 ("같은 HTML 그대로" → "루트 + 장면 파일 구조, PDF 는 같은 장면 파일에서 인쇄용 페이지 생성"). 근거는 `docs/tool-findings.md` 의 덱 절 3개.
