# 기획: 하나의 대본에서 HTML·PDF·MP4 (발표 우선)

작성 2026-10-30. 2026-10-30 대화에서 나온 방향을 정리했다. **직접 실행해 검증한 것은 아직 없다** (원칙 6).
근거 표기: **[문서]** CLI 도움말·ADR·저장소를 직접 확인 / **[2차]** 웹 검색 요약 / **[추정]** 판단 / **[미검증]** phase-02 에서 실측.
결정은 `docs/decisions/ADR-003`(출력 형식), `ADR-004`(구조, proposed)에 있다.

## 1. 방향

- 결과물은 **PDF(정적 자료), HTML(화살표로 진행하는 발표), MP4(자동 재생)** 세 가지다. PPTX 는 하지 않는다.
- 하나의 스크립트(대본)에서 에이전트가 이미지·애니메이션 같은 자산을 **제안**하고 사용자가 승인하며 진행한다.
- 첫 단계는 **발표 우선**이다: 대본을 쓰면 바로 발표 모드로 열고, 결과가 좋을 때만 PDF·MP4 로 후속 처리한다.

## 2. 형식별 가능성

| 형식 | 가능성 | 방법 | 한계 |
|---|---|---|---|
| MP4/WebM/GIF | 됨 [문서] | `hyperframes render --format` | 8초 클립 약 20~40초 (draft, spec-01-03 실측) |
| PNG | 됨 [문서] | `snapshot --at` | 슬라이드마다 "완성된 순간" 시각이 필요 |
| HTML 발표 | 가능성 높음 [추정] | `present`(발표자 모드, 화살표·전환은 [미검증]) 또는 직접 구현 | `/slideshow` 스킬 미설치로 동작 미확인 |
| PDF | 가능 [추정] | HTML 인쇄 모드 → 헤드리스 Chrome | 영상용 HTML 은 1920x1080 고정·`overflow:hidden`·GSAP 이라 그대로 인쇄하면 안 됨 [문서]. 16:9 고정 페이지 + 인쇄 모드(최종 상태) 설계가 필요 [미검증] |
| PPTX | 하지 않음 | - | 사용자 결정. 이펙트가 PowerPoint 고유 전환으로 줄어든다 [추정] |

## 3. 핵심 모델: 슬라이드 = 최종 상태 + 순서 있는 단계(step)

```
슬라이드 { 텍스트, 이미지 참조, steps[ {효과, 지속 시간} ... ] }
```
- **HTML**: 화살표를 누르면 다음 단계로 진행 (GSAP 타임라인 라벨 간 이동) [미검증]
- **MP4**: 같은 타임라인을 처음부터 끝까지 `render`
- **PDF**: 모든 단계가 끝난 최종 상태를 슬라이드당 한 페이지로 인쇄

영상과 발표가 같은 애니메이션 코드를 쓴다. 대본(Content Manifest)은 슬라이드별 텍스트, 이미지 참조, 단계 목록, 단계 시간을 담는 최소 구조로 시작하며 새 프레임워크는 만들지 않는다 (원칙 6).
에이전트가 쓸 **효과 어휘를 제한**해야 결과가 들쭉날쭉하지 않다 [추정].

## 4. UI 흐름 (초안, 맨 뒤에 만든다)

```
┌ 1 스크립트 ─ 2 자산 ─ 3 발표/미리보기 ─ 4 내보내기 ─ 5 게시 ┐
│ 단계 목록 │        가운데: 현재 단계의 작업 영역         │ 에이전트 제안 │
```

| 단계 | 사용자 | 에이전트 |
|---|---|---|
| 1 스크립트 | 슬라이드별 텍스트·단계 작성 | 구조 정리, 문장 다듬기 제안 |
| (즉시) 발표 | 자산 없이 텍스트 기본 레이아웃으로 바로 발표 | - |
| 2 자산 | 제안을 승인/거절/교체 | 슬라이드별 이미지·애니메이션·(선택) 효과음 제안과 근거 |
| 3 미리보기 | 화살표로 넘겨 보며 단계 시간 조정 | 겹침·대비 같은 문제 지적 |
| 4 내보내기 | PDF 다운로드, MP4 렌더 | 결과 검사(ffprobe, 프레임) 리포트 |
| 5 게시 | 제목·설명·공개 범위 확인 후 **직접 승인** | 초안 작성만 |

원칙:
- 음성·음악·효과음은 **기본 꺼짐**, 사용자가 요청할 때만 제안한다.
- 에이전트 제안은 항상 사용자 승인을 거치고, 승인된 자산을 덮어쓰지 않는다.
- YouTube 업로드는 OAuth·API 승인이 필요하고 심사받지 않은 API 프로젝트는 공개 업로드가 제한된다고 알고 있으나 확인하지 않았다 [미검증]. 사용자 승인 없이 게시하지 않는다.
- 렌더(PDF·MP4)는 브라우저만으로 안 되므로 로컬 Node 서버가 어댑터로 호출한다 (ADR-004).

## 5. 다음 단계: phase-02 시험 (제안)

phase-01 회고 후 닫고, phase-02 에서 **5장짜리 대본 하나로 세 출력을 끝까지** 만든다. 기존 자산(블록·자막)만 쓴다.

| 출력 | 성공 기준 (눈으로 확인) |
|---|---|
| PDF | 페이지 수가 슬라이드 수와 같고 글자가 선택된다. 잘림·애니메이션 중간 상태가 없다 |
| HTML | 브라우저에서 화살표를 실제로 눌러 단계가 순서대로 진행된다 |
| MP4 | `ffprobe` 검사 통과, 단계 시간이 대본과 일치, 프레임으로 확인 |

조사 선행 (원칙 1): `present`/`preview`가 단계 진행·전환을 어디까지 지원하는지, `/slideshow` 스킬과 reveal.js 같은 기존 덱 도구를 먼저 본다. 스킬 설치는 spec 근거와 사용자 확인 후에만 한다.
그 뒤에 에이전트가 대본에서 이미지·인터랙션을 만드는 루프를 붙이고, 마지막에 UI 를 입힌다.

## 6. 자산 생성과 Hypit

ADR-002 조사 기준 (2026-10-27, 이번에 재확인 안 함, 법률 검토 아님) [문서]: Hypit 은 생성 모델·음성 정렬이 강점이고 예시 기준 18~26초 클립당 약 $1.1 이다. 수정 Apache-2.0 으로 본인 조직 업무 사용은 허용하고 **SaaS 제공·재판매는 금지**한다.
- 위치: **2단계(자산 구축)의 "생성" 공급자**. 기존 자산으로 부족한 이미지·짧은 영상 클립을 에이전트가 제안하는 선택지다. 나중에 음성 phase 에서 음성·장면 정렬 후보가 될 수 있다. 렌더링(발표·PDF·MP4)에는 쓰지 않는다 (렌더는 HyperFrames).
- 조건: 어댑터 뒤에 두고 **기본값 꺼짐**. 유료이므로 건당 비용을 보여 주고 사용자가 승인한 호출만 한다. 횟수·비용 상한을 둔다. 도구가 없거나 실패하면 모의 결과를 만들지 않는다.
- 시점: phase-02 에서는 쓰지 않는다. 자산 제안 단계를 만들 때 클립 1~2개로 비용·품질을 확인한다.
- 이 프로젝트를 다른 사람에게 서비스로 제공하면 Hypit 사용은 라이선스로 막힐 수 있다 (§7 질문 1).

## 7. 열린 질문 (결정 필요)

1. **개인 제작 도구인가, 다른 사람에게 파는 제품인가?** 미정. 제품이라면 Hypit 사용 가능 여부, 클라우드 렌더, 경쟁(아래)을 다시 검토해야 한다.
2. 첫 영상·자료를 누가 보는가 (본인 채널, 포트폴리오, 판매용 등). "충분히 좋은 쇼케이스"의 기준이 여기서 나온다.
3. 이미지 출처: 처음에는 기존 자산(레지스트리 블록, `assets/`)만 쓴다고 잠정 합의했다. 생성 도구는 미정.
4. `/slideshow` 스킬 설치 여부 (스킬 변경은 spec 필요, `docs/project-principles.md`).
5. phase-01 성공 기준 4(라이선스·크레딧 방침)와 5(Hypit 라이선스 기록)가 기록됐는지는 확인하지 않았다. phase 회고에서 확인한다.

## 8. 비슷한 서비스와의 관계 [2차]

웹 검색 요약이며 직접 써 보지 않았다. 일부 글은 오래된 것을 제목만 2026 으로 바꾼 것이다.
- **Genspark**: 프롬프트로 덱을 만들고 PPTX/PDF 내보내기, AI 내레이션 영상, 이미지·영상 생성이 있다. 단점으로 크레딧 소모와 평범한 디자인이 언급된다.
- **NotebookLM**: 문서로 내레이션 영상과 슬라이드를 만든다. 슬라이드는 PDF/PPTX 로 받지만 슬라이드당 이미지 한 장이라 편집이 안 된다.
- **Gamma**: 편집 가능한 덱, PDF 내보내기, 발표, 링크 공유. 영상 내보내기는 확인하지 못했다.
- **판단 [추정]**: 범용 AI 덱 생성기로 경쟁하는 것은 승산이 낮다. 차별점 후보는 (1) 한 번 정의한 슬라이드 단계가 세 형식에 같은 애니메이션으로 나오는 구조 (2) 결과가 HTML 코드라 직접 소유하고 문구만 바꿔 재생성 (3) 자산 제안·승인 흐름과 게시까지의 연결이다. 시장성은 질문 1 에 달려 있다.
