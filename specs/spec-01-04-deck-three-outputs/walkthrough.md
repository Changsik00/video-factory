## 💬 사용자 협의

- **주제**: 핵심 기능 검증 여부 — 사용자가 "대부분 미검증이라면 기능 검토를 해야 하지 않나"라고 지적. 슬라이드쇼 스킬 문서에서 "덱은 MP4 로 렌더하지 마라"를 발견해 이 spec 으로 검증하기로 합의
- **주제**: 스킬 설치 — 사용자가 설치를 승인했으나 명령이 홈 디렉터리에 4개를 설치함(미리 안내한 "이 스킬만"이 틀림). `media-use` 는 프로젝트 원칙 위반이라 삭제, 홈의 나머지 설치분도 삭제하고 프로젝트로 복사. 사용자가 이 처리 방식을 승인함
- **사용자 판정**: 브라우저에서 직접 눌러 본 체감 확인은 **받지 못했다.** 자동화한 키 입력 검증만 했다

### 수동 검증
1. **V1 `present`**: 3장 덱(fragment 7s, 10s)을 서버로 띄우고 헤드리스 Chrome 에 실제 키 이벤트를 입력 → ArrowRight/Space 다음, ArrowLeft 이전, 슬라이드 1→2(첫 fragment)→2(둘째 fragment)→3, 끝에서 정지, 되돌아가기 확인 (스크린샷). 전환 애니메이션·청중 동기화 미확인
2. **V2 `render`**: 루트 없음 4.0초(첫 장면만, 문서 재현), 루트 있음 16.0초 1920x1080 h264, 프레임 5장으로 장면·항목 시점 확인
3. **V3 PDF**: 이미지 PDF 3쪽(글자 0자), 인쇄 PDF 3쪽 벡터(글자 231자, 폰트 임베드), 최종 상태 프레임 확인
4. **V5 YouTube**: 공식 문서 기준 정리. 미검증 프로젝트의 비공개 제한 규칙이 문서끼리 충돌 (업로드 안 함)

## 🔍 발견 사항

- **ADR-003 결정 2 를 수정했다**: "같은 HTML" → "루트 + 장면 파일 구조에서 present·render 공유, PDF 는 같은 장면 파일에서 인쇄용 페이지 생성". 스킬 문서의 "덱 렌더 불가"는 루트 없는 구조에서의 증상이었다 (소리·분기 슬라이드가 있으면 다른 이유로 맞을 수 있음, 미확인)
- `check --json` 은 동작하지 않는 덱 구조도 통과시킨다. 덱 오류는 `present` 콘솔(`manifest errors`)과 키 진행으로만 보인다
- fragment 가 있는 슬라이드는 첫 fragment 시각에서 진입한다 (항목을 하나씩 보이려면 fragment 를 항목 수만큼)
- `snapshot --at` 은 영상 끝 프레임을 한 장 더 만든다
- 인쇄용 페이지는 장면 스크립트의 전역 `const` 충돌, 런타임 없는 `window.__timelines` 가정 때문에 생성 시 보정이 필요하다 (처음에는 글자가 투명한 PDF 가 나옴)
- `present` 컴포넌트가 없는 `/composition/sfx/*.mp3` 를 요청해 404 가 난다 (진행에는 영향 없음)
- 스킬 설치 명령의 부작용(홈에 4개 설치)을 겪었다. `.claude/settings.json` 의 `HYPERFRAMES_SKIP_SKILLS=1` 이 의도대로 설치를 막고 있었다
