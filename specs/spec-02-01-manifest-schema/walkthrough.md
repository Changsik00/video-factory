## 💬 사용자 협의

- **주제**: 스키마 모양 — spec 에서 "로컬 시각 + 단계 번호 모델로 괜찮은가"를 확인 요청했고, 사용자는 별도 수정 요구 없이 Plan Accept 로 승인했다
- **참고**: 사용자가 "harness-kit 이 이상하게 진행하는 것 같다, 다음 작업이 없는가"를 물어 `sdd status` 의 `NEXT: 없음`, Tasks 카운트(하위 항목 포함 23개), `Last Test` 시각이 헷갈리는 이유를 설명했다. 도구 변경은 하지 않았다

## 🔍 발견 사항

- 구현 중 테스트 기대값 2건을 정정했다 (red 커밋 이후): 최상위 알 수 없는 필드의 `path` 를 필드 이름으로 통일, `{step}` 만 있는 항목 사례에 `steps` 를 추가해 한 가지 오류만 검증하도록
- `present` 의 "첫 fragment 에서 진입" 규칙 때문에 단계 0 의 항목은 진입 즉시 보인다. 슬라이드가 "아무것도 안 보이는 상태"로 시작할 수는 없다. 스키마 문서에 적었고 생성기에서 영향이 있는지 spec-02-02 에서 확인한다
- eslint 가 설치되어 있지 않아 커밋 훅의 lint 는 건너뛰었다 (경고만 출력, 변경 없음)
- 스키마는 슬라이드 하나에 이미지 하나만 허용한다. 여러 이미지·레이아웃은 아직 없다

## 🚧 이월 항목

- 명세에서 덱(루트 + 장면 파일)을 만드는 생성기와 `present` 진행의 자동 확인 (spec-02-02): `items[].step` 을 GSAP 트윈 시각(단계 직전)으로 바꾸는 규칙, 장면 id 와 호스트 id 일치 규칙

- 분기 슬라이드, 소리, 전환 효과, 이미지 외 자산은 스키마에 없음
- `sdd status` 가 계획된 spec 을 `NEXT` 로 보여 주지 못하는 문제는 도구 쪽이라 이번에 다루지 않았다
